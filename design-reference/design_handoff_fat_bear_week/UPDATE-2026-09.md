# Update prompt: Fat Bear Week party app

This supersedes the earlier handoff for everything it covers. `README.md` in this folder still describes the overall product, data model, identity approach and future phases — read it first. This file lists what changed in the design since that README was written, and gives the final copy verbatim.

The reference prototype `Fat Bear Week Invite.dc.html` in this folder is current. When this document and the README disagree, **this document wins**. When this document and the prototype disagree, the prototype wins.

---

## 1. The invite is now in two parts

The invite screen is explicitly split. Everything about **this party** comes first; everything about **Fat Bear Week the phenomenon** comes second, under a heading. Order of blocks in the invite body, top to bottom:

**Part one — the party**
1. Intro paragraph
2. GAME DETAILS table
3. Bullet list (2 bullets)
4. COSTUME ENCOURAGED card
5. YOUR STATUS card (only when a guest is identified)
6. Two coming-soon tiles (potluck, bracket)
7. "See who's coming" link

**Part two — the background**
8. Section heading: **WTH IS FAT BEAR WEEK?**
9. LIVE FROM KATMAI cam carousel
10. Explainer paragraph
11. SCOUTING DEPARTMENT card
12. BROADCAST SCHEDULE card

The part-two heading is a wrapper with `border-top: 2px solid #1F3B2C; padding-top: 20px`, containing one line: Archivo Black, 24px, line-height 1.05, uppercase, `#1F3B2C`. No eyebrow label, no subhead.

A sticky RSVP bar sits at the bottom of the invite view, below all of it.

## 3. New feature: broadcast schedule

A card listing explore.org's live bearcam events. **Data-driven, not hardcoded markup** — the host needs to edit this list each season.

Event shape: `{ iso, day, date, title, times, desc, url, big }`

Behavior:
- Only events whose start time is less than 2 hours in the past are shown; the list self-prunes as the week goes.
- If nothing is upcoming, show the empty-state line.
- `big: true` marks the headline event. Its date chip uses `#A84322` background with `#FFF8EA` text; normal chips use `#F5EDDC` background, `#7A7266` day label, `#1F3B2C` number.

Row layout: a 54px date chip (day abbreviation 11px/700/0.1em above the date in Archivo Black 20px) on the left, then title (16px/600), times (13px/600, `#7A7266`), description (14px, `#6E675B`), and a `Watch on YouTube ↗` link (14px/600, `#2F6B7A`, 44px min-height).

## 4. New feature: bear allegiance

A guest who has RSVP'd yes can optionally declare a bear. Stored as `Guest.bear` (free text, nullable).

- **RSVP screen**, below the guest stepper: a `DECLARE A BEAR · OPTIONAL` card. Explainer, then five pill chips — **Grazer, Chunk, 747, Holly, Undecided** — then a free-text input (`Or type a bear (128, Holly, 856…)`) with a `SET` button. Tapping the selected chip clears the allegiance. Chips are 999px radius, `min-height: 44px`, selected = `#1F3B2C` bg / `#FBF4E4` text, unselected = white / `#1F3B2C` text / `#DED3BC` border.
- Explainer copy: "Allegiance usually happens after scouting, but if you already have a bear, stake your claim now. You can switch before brackets lock." plus a `Read up on the bears ↗` link to the Brooks River ebook.
- **Invite**, in YOUR STATUS: a `TEAM {BEAR}` pill.
- **Check-in strip**: the tagline becomes ` · in · Team {bear}`.
- **Roster**: `TEAM {BEAR}` under the guest's name, 12px/700/0.1em, `#C2522E`.
- **Press box**: status column reads `IN · {bear}`.
- Withdrawing an RSVP and the host's reset both clear `bear`.

Do not treat the chip list as fixed — it is a per-season editorial choice, so it should be data.

## 5. Host view is hidden

The Press Box link renders in the nav **only** when the URL carries `?host` or `#host`. Double-clicking the "FAT BEAR HQ" wordmark also navigates there (a desktop-only convenience; it does not work on touch). In production use a separate unguessable host URL. Guests must not reach the reset-all control by accident.

## 6. Mobile rules that must survive the port

The prototype was tuned against a 375px viewport. These are requirements, not preferences:

- **Body text 16–17px. Secondary text 14–15px. Labels 11–12px. Nothing below 11px.**
- **Every text input is at least 16px** — under that, iOS Safari zooms the page on focus and does not zoom back out.
- **Every interactive element is at least 44px tall**, including bare text links ("Not you?", "Back to the invite", "Withdraw my RSVP entirely", "Open the cam", "Watch on YouTube"). Prefer `min-height: 44px` with `display: inline-flex; align-items: center` over vertical padding — padding gets tuned away later, `min-height` does not.
- **The sticky bottom bar pads for the home indicator**: `padding-bottom: calc(12px + env(safe-area-inset-bottom))`.
- **The cam thumbnail rail must show a partial fourth thumbnail** at 375px so the horizontal scroll is discoverable (118px tiles achieve this).
- **Contrast**: 4.5:1 minimum for anything under ~19px. `#7A7266` is the tertiary-text token; `#8A8071` was retired for failing on cream.
- The host table's status column is fixed at 96px with `flex: none` and wraps; the guest name column ellipses.

## 8. Known gaps, deliberately left

- **Add to calendar** was built and then removed by the client. If it comes back, generate a real `.ics` (the party is Oct 2 2026, 7:00–11:00 PM America/Denver) rather than a Google Calendar link, so it works on iOS.
- **explore.org cams do not embed.** Only the YouTube feed (`https://www.youtube.com/embed/EwTH5yY7Mks`) plays inline; the other four cams show a striped placeholder with a link out. Cam IDs change season to season, so keep the cam list as data.
- **Potluck and bracket** are still unbuilt. See the README's "Future phases" section.
- `See who's coming (N confirmed)` counts **heads**, not people, so the number includes plus-ones while the word reads as guests. Worth resolving during the build.
